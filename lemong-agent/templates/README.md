# Lemong-Music 模板设计说明

> **关联文档**: `/workspace/docs/standard/ACE-Step1.5参考资料.md`（ACE 参数参考源）  
> **最后更新**: 2026-07-14

---

## 一、设计原则

### 1.1 模板定位

每个模板文件是一个**静态的交互式问卷**。模板本身不执行逻辑，由 Skill（Lemong-Music）加载并按模板预设的问题顺序向用户提问，逐步收集创作所需的全部信息。

### 1.2 核心原则

| 原则 | 说明 |
|------|------|
| **渐进式收集** | 从宏观到微观，从主题到细节，避免一次性抛出过多问题 |
| **风格特有化** | 每种风格的问题维度不同（如古风问诗词意象，电子问合成器偏好） |
| **参数全覆盖** | 收集的信息应足以生成歌词和歌曲两个方向的完整提示词 |
| **参考 ACE 参数** | 问题设计覆盖 ACE Step1.5 的所有可预设参数（详见参考资料） |
| **可跳过** | 非必填问题提供默认值，用户可跳过保持流畅感 |

## 二、模板结构规范

每个模板文件（`风格名.md`）必须包含以下章节：

```markdown
# {风格名} — 创作问卷

## 基本信息
### 1. 歌曲主题
### 2. 核心情感
### 3. 目标时长

## 歌词维度
### 4. 歌词结构偏好
### 5. 关键词/意象
### 6. 叙事视角

## 音乐维度
### 7. 节奏与速度
### 8. 调式与和声
### 9. 和弦走向
### 10. 乐器配置
### 11. 人声风格

## 技术参数
### 12. 输出格式
### 13. 特殊要求

## 默认值汇总
## 生成的提示词格式
```

### 2.1 问题设计规范

每个问题包含以下字段：

```markdown
### N. {问题标题}

**问题**: {向用户提出的问题文本}

**选项/示例**:
- {选项1}
- {选项2}
- {自定义}

**默认值**: {用户跳过时采用的值}

**用途**: {该答案将用于生成歌词还是歌曲提示词，或两者}
```

### 2.2 问题顺序逻辑

1. **基本信息**（主题/情感/时长）→ 定基调
2. **歌词维度**（结构/意象/视角）→ 细化内容
3. **音乐维度**（节奏/调式/和弦/乐器/人声）→ 细化声音
4. **技术参数**（格式/特殊要求）→ 收尾

## 三、信息收集 → 提示词生成

### 3.1 工作流程

```
用户触发音乐创作意图
    ↓
Skill 加载对应风格的模板文件
    ↓
Skill 询问是否选择预定义歌手
    ├── 选择歌手 → 加载 singer/{歌手名}/profile.json
    └── 不选择（默认）→ 跳过
    ↓
Skill 按模板问题顺序逐一向用户提问
    ↓ （收集全部信息后）
Skill 将收集到的信息 + 歌手特征传递给 LLM
    ↓
LLM 生成两部分输出：
  ┌─────────────────────────────────────┐
  │ A. 歌词（结构化）                    │
  │    - 歌名（用于文件命名）             │
  │    - 段落标注（[主歌]/[副歌]/[桥段]） │
  │    - 完整歌词文本                    │
  │    - 押韵/情感递进说明               │
  ├─────────────────────────────────────┤
  │ B. 歌曲提示词（给 ACE API）          │
  │    - 风格描述（英文）                │
  │    - 乐器配置                        │
  │    - BPM / Key / Time Signature     │
  │    - 情绪与氛围描述                  │
  │    - 人声语言与风格                  │
  └─────────────────────────────────────┘
    ↓
用户审阅 → 修改（回到修改循环）→ 确认
    ↓
歌词确认后，调用 generate-music.js 生成音乐
```

### 3.2 文件命名规范

| 阶段 | 歌词文件 | 歌曲文件 |
|------|----------|----------|
| 创作中 | `歌名_V1.json` | `歌名_V1.mp3` |
| 修改后 | `歌名_V2.json` | `歌名_V2.mp3` |
| 确认成品 | `歌名.json` | `歌名.mp3` |

- **歌名**由 LLM 在生成歌词时一并产出
- 文件名中的特殊字符替换为 `_`
- 成品文件覆盖同名旧版本

### 3.3 歌词确认后的音乐迭代

```
确认歌词
  ↓
调用 generate-music.js → 输出 歌名_V1.mp3
  ↓
用户试听 → 不满意？
  ↓ 是
用户提供修改方向（如"节奏快一点""加入弦乐"）
  ↓
Skill 调整歌曲提示词 → 重新生成 → 歌名_V2.mp3
  ↓
用户试听 → 确认成品
  ↓
重命名为 歌名.mp3，保存 歌名.json
```

## 四、与 ACE Step1.5 参数映射

模板收集的信息最终映射到 ACE API 参数：

| 模板维度 | ACE 参数 | 说明 |
|----------|----------|------|
| 歌曲主题 / 核心情感 | `caption` | 风格与音色描述（英文） |
| 歌词结构 / 关键词 / 叙事视角 | `lyrics` | 歌词文本 |
| 目标时长 | `duration` | 音频长度（秒） |
| 节奏与速度 | `bpm` | 节拍速度 |
| 调式与和声 | `key_scale` | 调式 |
| 和弦走向 | `caption` | 作为风格描述的一部分传入 ACE |
| 特殊要求 | `time_signature` | 拍号 |
| 人声风格 | `vocal_language` | 人声语言 |
| 输出格式 | `audio_format` | mp3/wav/flac |
| 质量要求 | `thinking` | 是否启用 5Hz LM |

> 完整参数说明参见 `/workspace/docs/standard/ACE-Step1.5参考资料.md`

## 六、Skill 调用模板的方式

Skill 加载模板时应遵循以下逻辑：

1. 解析模板 Markdown，提取所有问题及其顺序
2. 逐题向用户展示，等待用户回答（或输入"跳过"使用默认值）
3. 所有问题收集完毕后，将答案组装为结构化上下文
4. 调用 LLM（DeepSeek V4），传入系统提示词 + 用户答案上下文
5. LLM 输出：歌词 JSON + 歌曲提示词
6. 展示给用户审阅，进入确认/修改循环
