### 2. 工作台 `a-o-c.cc.cd` 备案拦截修复

- **问题**: 经 Cloudflare 橙云代理访问 → 腾讯云 → 521 错误（未备案拦截）
- **根因**: Cloudflare 代理节点发出的入站 HTTP 被腾讯云按域名筛选拦截
- 连带问题：Let's Encrypt HTTP-01 验证同样被重定向到 `dnspod.qcloud.com` 拦截页

**解决方案 — DNS-only + DNS-01 SSL**:

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | DNS 切灰云 (`proxied: false`) | `a-o-c.cc.cd` → `182.254.180.26`，绕过 Cloudflare 代理 |
| 2 | 安装 `certbot-dns-cloudflare` | DNS-01 验证插件（绕过 HTTP 拦截） |
| 3 | 签发 Let's Encrypt 证书 | DNS-01 验证通过 Cloudflare API 创建 TXT 记录 |
| 4 | Nginx v4 部署 | 新增 HTTPS 443 + HTTP→HTTPS 跳转 + HSTS |

**验证**:

| URL | 状态码 | 说明 |
|-----|--------|------|
| `http://a-o-c.cc.cd/` | 301 → HTTPS | HTTP 强制跳转 |
| `https://a-o-c.cc.cd/` | 301 → `/workbench/` | 默认跳工作台 |
| `https://a-o-c.cc.cd/workbench/` | 200 | Admin-UI SPA 正常 |
| `https://a-o-c.cc.cd/admin/dashboard` | 200 | Coordinator API 正常 |

### 🔴 工作台登录机制改造

**当前状态**: 使用 HTTP Basic Auth (帐号密码) 登录

**目标**: 改为与 iLink-bot 相同的微信 ID 体系，通过二维码扫码验证身份

**改造要求**:
1. 去掉帐号密码登录方式
2. 用微信扫码替代：前端展示二维码 → 用户微信扫码 → 后台验证微信 OpenID → 发放 Session Token
3. 与 iLink-bot 共用一个微信用户 ID 体系（统一身份认证）
4. 移除 `coordinator-agent/src/middleware/auth.js` 中的 Basic Auth 逻辑，替换为 JWT + 微信验证

**技术方案参考**: OAuth2 Authorization Code 流程：
- Admin-UI → 请求二维码 → Coordinator 生成临时 token → 返回二维码 URL（指向微信 OAuth）
- 用户扫码授权 → 微信回调 → Coordinator 交换 access_token → 获取 OpenID → 签发 JWT
- Admin-UI 持有 JWT 访问所有 Admin API
