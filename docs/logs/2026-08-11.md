## 分析结论

### Website vs Admin-UI 部署方式对比

| 维度 | Website (mirage.cc.cd) | Admin-UI (a-o-c.cc.cd) |
|------|----------------------|------------------------|
| 框架 | Astro SSG | React SPA (Vite) |
| 输出 | 纯静态 HTML | JS bundle + 动态 API 调用 |
| CI/CD | ✅ GitHub Actions → Cloudflare Pages | ❌ 无 CI，手动本地构建 + scp |
| 部署目标 | Cloudflare Pages CDN | 4C4G Nginx 静态 serve |
| DNS | 橙云 (proxied) | 灰云 (DNS-only) |
| SSL | Cloudflare 自动 | Let's Encrypt DNS-01 |
| 后端依赖 | 无 | Coordinator API (localhost:3100) |

**是否都使用了 GitHub Actions？**
- Website：是，`.github/workflows/deploy-website.yml` → Cloudflare Pages
- Admin-UI：否，手动构建 + scp 部署。原因：从 2026-08-09 开始一直手动部署，GitHub Actions 只配置了 website 流水线。

**技术栈差异是否影响部署方式？**
- 直接影响。Astro SSG 生成完整 HTML，可部署到任何 CDN。React SPA 需要同域 API 代理，所以必须与后端共存服务器。
- 如果 Admin-UI 也用 Cloudflare Pages 部署，需要 Coordinator API 暴露到公网（安全风险 + 备案拦截），不可行。

### 网关与未来架构建议

**结论：Admin-UI 当前静态部署方案完全适用，网关功能应加在 Coordinator 后端。**
