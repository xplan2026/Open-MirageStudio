| `rm -rf /opt/xplan_backup_*/` | 删除旧备份 |

### 部署步骤

1. **打包上传**: `tar czf` 排除 node_modules → `scp` 到服务器 → `tar xzf`
2. **安装依赖**: `npm install --production`（coordinator 72 packages）
3. **构建 Admin UI**: `npm install` + `npm run build` → `dist/`
4. **环境变量**: 从本地 `.env` 提取 `DEEPSEEK_*` / `ZHIPU_*` → 写入远程 `.env`
5. **PM2 启动**: `pm2 start src/index.js --name coordinator` → 端口 3100
6. **Nginx 配置**: 替换旧 `jjzz-music` 配置，部署 `coordinator.conf`（Admin UI + API 反代 + A2A）

### 关键 Bug 修复：ESM dotenv 加载顺序

**问题**: `dotenv.config()` 写在 `index.js` 顶部，但 ESM 静态导入在所有代码执行前求值，导致 `parser.js` 中的 `process.env.DEEPSEEK_API_KEY` 在导入时为 `undefined`，意图解析降级到关键词匹配模式。

**修复**: 创建 `src/env.mjs` 独立模块，在 `index.js` 中作为第一个 import 引入。ESM 按依赖顺序求值，`env.mjs`（无业务依赖）最先执行 `dotenv.config()`，后续模块导入时可正确读取环境变量。

**验证**: `[IntentParser] DeepSeek 解析成功`，confidence 从 0.6 → 0.95。
