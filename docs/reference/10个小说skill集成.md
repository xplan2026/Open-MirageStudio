## 背景

作者在尝试 AI 视频（成本高、质量不稳）和 AI 小程序（流程繁琐）后，发现**写小说试错成本最低**——几十块钱的 AI Token 就能写十几万字。已在番茄/七猫/起点等平台签约并产生稿费收益。

但直接让 AI 写长篇小说会遇到三大难题：
1. **世界观构建难**：时间、物价、地图设定混乱
2. **角色管理难**：性格前后不一，关系网混乱
3. **大纲编排难**：爽点、钩子、情绪曲线无章法

解决方案：开发一套 **Skill 辅助工作流**，而非 AI 全自动生成。由人掌控创意和决策，工具负责管理设定、角色状态、逻辑一致性。

---

## 十大 Skill 模块

### 1. 扫榜与拆文 (NOVEL-ANALYZE)

| 维度 | 说明 |
|------|------|
| **功能** | 分析热门榜单趋势，拆解爆款题材、人设、爽点密度、更新策略 |
| **产出** | 快速摸清市场需求，沉淀可复用的"模块库" |

### 2. 大纲编排 (NOVEL-OUTLINE)

| 维度 | 说明 |
|------|------|
| **功能** | 搭建故事骨架：卷章结构、细纲、爽点位置、情绪曲线、钩子设计 |
| **特色** | 支持多线大纲 + **蝴蝶效应分叉**：系统追踪设定变更对后续章节的影响 |

> 核心价值：防止修改前面导致后面剧情错乱。

### 3. 角色档案 (NOVEL-CHARACTER)

| 维度 | 说明 |
|------|------|
| **功能** | 为角色建立"身份证"：外貌、性格标签、说话风格、情绪状态、能力值、关系网、成长弧线 |
| **效果** | 每次续写前 AI 读取该卡，防止角色崩坏 (OOC)，生成关系图谱 |

### 4. 知识库管理 (NOVEL-KNOWLEDGE)

| 维度 | 说明 |
|------|------|
| **功能** | 故事中的"百度百科"：时间线、物价锚点、品牌对照、流行文化 |
| **技术** | 防止年代穿帮（如 1998 年出现 iPhone）；支持本地 RAG，上传参考资料可 Embedding 检索 |

### 5. 世界构建 (NOVEL-WORLDBUILDING)

| 维度 | 说明 |
|------|------|
| **功能** | 世界观总览、动态迷雾地图、历法、种族/职业、规则体系、文化禁忌 |
| **机制** | 核心设定可上锁，修改需走变更流程；每章写完扫描正文，提示与现有设定的冲突点 |

### 6. 逻辑预防 (NOVEL-LOGIC) ⭐ 核心防崩护栏

| 维度 | 说明 |
|------|------|
| **微逻辑卡** | 每个场景动笔前强制填写：谁在场？在哪？知道什么？想要什么？ |
| **动作前四问** | 谁在场？刚才在哪？为何这么做？信息/道具哪来的？ |
| **产出** | "逻辑矩阵" + "知情边界"追踪表，杜绝时间倒流、空间瞬移、信息穿帮 |

### 7. 进度管理 (NOVEL-PROGRESS)

| 维度 | 说明 |
|------|------|
| **功能** | 写作台账：章节树、字数统计、状态流转（未写/草稿/精修/定稿）、写作日历、钩子追踪 |
| **创新** | **章节切片技术**：每章定稿后只保留关键信息，后续写作只读最近 10 个切片而非全文，解决长篇小说后期上下文长度限制 |

### 8. 写作核心 (NOVEL-WRITING)

| 维度 | 说明 |
|------|------|
| **功能** | 整合大纲、角色、知识库、进度、质检能力，提供细纲→正文的完整写作流程 |
| **机制** | 上下文自动注入（续写时自动读大纲、角色卡、前文摘要）；区分"写作模式"和"修改模式"节省 Token |

### 9. 去 AI 味质检 (NOVEL-HUMANIZER)

| 维度 | 说明 |
|------|------|
| **问题** | AI 写作的"机翻味"：如"嘴角微微上扬""眼中闪过一丝寒光" |
| **方法** | 从文学性、节奏感、对话自然度、时代适配度、情感表达等 **9 个维度**打分，生成雷达图 + 修改建议，支持"人化改写" |

### 10. 多视角审稿 (NOVEL-REVIEW)

| 视角 | 关注点 |
|------|--------|
| 编辑视角 | 商业价值和节奏 |
| 读者视角 | 代入感和期待感 |
| 平台视角 | 推荐机制适配度 |
| 作者视角 | 设定一致性和伏笔回收 |

## 使用方式与门槛

- **形态**：基于 VS Code 的插件，推荐搭配 Cline 使用
- **优势**：数据完全本地（隐私安全，可用 Git 版本管理），无服务器和订阅费
- **门槛**：有一定学习门槛，需跟着文档初始化项目；若不想折腾环境，可将 Skill 提示词复制到其他 AI 对话工具使用

---

## 快速开始

```bash
git clone https://github.com/Wooooooooood/ai-fiction-writer.git
cd ai-fiction-writer
# 按照「写作工作流」文档初始化项目，从「扫榜拆文」开始
```

## 对本项目的参考价值

1. **Skill 模块化设计**：10 个独立 Skill 各司其职，通过上下文自动注入协作——这是 Agent 设计的最佳实践，可直接借鉴到 lemong-agent 和 erhu-agent 的架构中
2. **上下文管理**：章节切片技术（只读最近 10 个切片）解决了长上下文问题，类似思路可用于长歌曲/MV 的多段生成
3. **逻辑预防机制**：微逻辑卡 + 动作前四问的概念可迁移到歌词叙事一致性检查
4. **去 AI 味质检**：9 维度打分 + 雷达图，类似方法可用于评估 AI 生成歌词的"人味"
5. **多视角审稿**：编辑/读者/平台/作者四视角审稿模式，可改编为歌曲的多维度评审
6. **人控 AI 辅助**：不是全自动生成，而是人做决策、AI 做执行——这与我们的 Agent 设计哲学一致
