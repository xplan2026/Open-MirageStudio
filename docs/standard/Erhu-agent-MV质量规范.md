# Erhu Agent (二虎) — MV 作品质量标准与规范

> 创建日期: 2026-07-18
> 版本: v1.0
> 状态: 已发布
> 参考来源: LibTV内容创作质量标准与规范（内部版）

---

## 概述

本规范整合了 **LibTV 视频作品创作质量标准** 中与 MV 制作相关的全部要求，并针对 Erhu Agent 的 AI 全自动工作流进行了适配与细化。所有二虎 MV 作品在制作和自检时应以本文档为权威参考。

### 适用范围

- Erhu Agent (二虎) 生成的所有 AI 音乐 MV 作品
- 作品评估、自检、迭代优化时的质量标准依据

---

## 一、基础质量标准

> 来源: LibTV 规范 §1，结合 Erhu Agent 实际能力适配

### 1.1 封面

| 等级 | 标准 | Erhu Agent 实现 |
|------|------|-----------------|
| **优质** | 封面清晰、美观，精准传达视频核心亮点或主旨，与内容高度匹配 | 从 images/ 中选取最具代表性的图片作为封面帧；可指定 `--cover-frame` 参数 |
| **普通** | 清晰度一般，与内容基本相符，但缺乏吸引力 | 自动选取第一张图片 |
| **低质** | 模糊、变形，与内容无关，或纯黑背景+文字（无标题） | 需避免 |

**Erhu 执行要点**:
- 封面应从副歌段图片中挑选（情绪最饱满的视觉）
- 禁止使用纯黑背景+艺术字作为封面
- 封面图应为 16:9 横版，分辨率 ≥ 1920×1080

### 1.2 标题

| 等级 | 标准 | Erhu Agent 实现 |
|------|------|-----------------|
| **优质** | 精准概括视频核心价值，语言精炼、无错别字 | 作品名即标题，管理员在计划文档中定义 |
| **普通** | 基本说明内容，但略显平淡、冗长 | — |
| **低质** | 与内容严重不符，存在夸大或夸张 | 需避免 |

**Erhu 执行要点**:
- 作品名应控制在 2-8 个汉字
- 避免使用纯英文标题（目标受众为中文用户）
- 标题不得夸大或误导（如 "史上最…"、"全网首发" 等）

### 1.3 时长

| 等级 | 标准 | Erhu Agent 实现 |
|------|------|-----------------|
| **优质** | 16s ~ 5min | 默认目标 2-4 分钟 |
| **普通** | < 15s 或 > 5min | — |
| **低质** | ≤ 10s | 需避免 |

**Erhu 执行要点**:
- 歌曲生成阶段应控制时长在 2-4 分钟（120s-240s）
- 最短不得低于 16 秒
- 超过 5 分钟的作品需在计划文档中明确标注原因

### 1.4 字幕

| 等级 | 标准 | Erhu Agent 实现 |
|------|------|-----------------|
| **优质** | 完整、准确，时间轴精确，字体清晰可读，位置合理，不影响画面主体；与画面有一定匹配度和美感 | 当前使用 `drawtext` 逐句显示，白字+黑色描边 |
| **普通** | 存在少量错别字或时间轴轻微偏差，但整体可理解 | — |
| **低质** | 严重错误、错位、无法辨认 | 需避免 |

**Erhu 执行要点**:
- 歌词字幕必须完整、无错别字（在 compose 阶段验证）
- 时间轴需与音频对齐（`--lyric-start` 参数精确设置）
- 字幕位置固定底部居中，不遮挡画面主体
- 字号 32px，白色字体 + 黑色描边（当前实现已满足）
- **远期改进**: 实现卡拉OK 逐字高亮效果（v1.1）

### 1.5 音频质量

| 等级 | 标准 | Erhu Agent 实现 |
|------|------|-----------------|
| **优质** | BGM 贴合视频情绪与节奏，人声/旁白清晰无杂音，无爆音、削波 | ACE API 生成，固定二虎音色模板 |
| **普通** | 音量略不均衡或风格匹配度一般，音画不同步 ≤ 3s | — |
| **低质** | 无 BGM（需要氛围场景下），BGM 音量严重失衡，人声模糊、爆音严重，音画不同步 > 3s | 需避免 |

**Erhu 执行要点**:
- 歌曲由 lemong-agent + ACE API 生成，音频质量取决于 API 输出
- 合成阶段确保音画同步（`-shortest` 参数以音频为准）
- 音量标准化: 输出前做一次 `loudnorm` 归一化（远期改进）
- 如 ACE 生成的音频存在明显瑕疵，应在计划文档中标注并重试

### 1.6 画质与分辨率

| 等级 | 标准 | Erhu Agent 实现 |
|------|------|-----------------|
| **优质** | 分辨率 ≥ 1080p，画面清晰锐利，无明显压缩、噪点或模糊区域 | 目标输出 1920×1080 H.264 |
| **普通** | 分辨率 720p 左右，画面整体可接受但细节模糊 | — |
| **低质** | 分辨率低于 720p，画面严重模糊 | 需避免 |

**Erhu 执行要点**:
- **硬性要求**: 最终输出必须为 1080p (1920×1080)
- 图片素材生成 1280×720 → 拉伸至 1920×1080（当前方案可接受）
- **远期改进**: 图片素材直接生成 1920×1080
- 视频编码: H.264 (libx264)，码率 ≥ 5Mbps

### 1.7 AI 生成质量与一致性

| 等级 | 标准 | Erhu Agent 实现 |
|------|------|-----------------|
| **优质** | 无明显 AI 生成瑕疵，人物肢体、光影、文字、物体运动均符合物理逻辑，画面连贯自然；整段视频主体形象连贯一致 | 目标标准 |
| **普通** | 存在轻微 AI 痕迹/瑕疵（如局部闪烁、手指轻微扭曲），但不影响整体理解和专业感；主体不一致 < 3s | 当前可接受 |
| **低质** | 明显 AI 瑕疵（面部模糊、文字模糊及出现/消失、画面撕裂）影响观感；视频出现 > 3s 主体不一致 | 需避免 |

**Erhu 执行要点**:
- 图片生成阶段：检查每张图片是否有明显 AI 瑕疵（面部模糊、手指异常、文字乱码）
- Ken Burns 效果本身不产生 AI 瑕疵，但源图片质量直接影响最终效果
- 同一首歌的图片风格应保持一致（同一 `imageStyle` 参数）
- 若使用 CogVideoX 生成动态视频，需逐段检查人物一致性

## 二、MV 垂类质量标准

> 来源: LibTV 规范 §2.2.2 风格美学、MV，核心参考标准

### 2.1 MV 定义与判定

**MV（Music Video）** 判定要点：
- 不要求传统叙事的"五要素"（主角、任务、情节、动机、场景）
- **但必须满足**: 音乐与画面完整对应 — 整首歌配画面，段落结构完整
- 用于音乐发行、艺人宣传、KTV 版等场景
- 可混合风格（写实 / 非写实），写实类 MV 优先

**Erhu Agent 定位**: 写实类 AI 音乐 MV（以乡村/民谣/古风为主）

### 2.2 视觉主题统一性

| 等级 | 标准 | Erhu Agent 实现 |
|------|------|-----------------|
| **优质** | 有清晰视觉符号或情绪曲线（由静至动、由冷到暖），开头结尾呼应；封面有画面感，能展示大致风格和主题 | 目标标准 |
| **普通** | 风格一致但表现单调，无情绪变化；画面直接对应歌词字面意思，无深度 | 当前基准 |
| **低质** | 风格杂乱无章，画面与歌词无关联 | 需避免 |

**Erhu 执行要点**:
- 整首歌的图片风格必须统一（由 `imageStyle` 参数控制）
- 图片 prompt 生成时需传递"视觉主题符号"概念（重复出现的视觉元素）
- 段落间应有情绪递进：
  - **前奏/Intro** → 空镜/氛围图（建立场景）
  - **A段/Verse** → 叙事画面（铺垫）
  - **B段/Pre-Chorus** → 情绪上升（画面色调逐渐变暖/变亮）
  - **副歌/Chorus** → 视觉高潮（最饱满、最富张力的画面）
  - **间奏/Instrumental** → 空镜/转场（情绪缓冲）
  - **尾奏/Outro** → 渐暗/呼应开头（收束）

### 2.3 视听语言

| 维度 | 优质标准 | 普通标准 | Erhu 当前实现 |
|------|---------|---------|--------------|
| **镜头语言** | 景别配置服务于音乐情绪与节奏，运动镜头与节奏/重音/旋律同步，视点转换增强流动感 | 景别变化但与音乐结构配合不够，运动镜头以基本推拉摇移为主 | Ken Burns 缩放+平移，交替方向 |
| **构图与空间** | 主体与留白比例服务于整体风格，非常规构图有明确美学意图，景深与氛围匹配 | 构图以常规或对称为主，缺乏明确美学意图 | 图片 prompt 阶段可控制构图 |
| **光影色彩** | 有明确风格倾向（高对比、柔光、锐光、单色等），色调统一且与音乐情绪呼应 | 光影均匀，色调统一但无突出风格 | 图片 prompt 阶段可控制 |
| **剪辑节奏** | 与音乐节奏、歌词、情绪呼应，镜头时长变化与音乐结构匹配 | 节奏基本匹配音乐，但无精心设计 | 等时长切分（每张图均分） |

**Erhu 执行要点**:
- **剪辑节奏优化（高优先级）**:
  - 当前为等时长切分，需改为按音乐结构分配时长
  - 副歌段: 图片切换加速（3-5s/张），增强节奏感
  - 叙事段: 正常速度（5-7s/张）
  - 前奏/间奏: 慢速（8-10s/张），营造氛围
- **镜头语言优化**:
  - Ken Burns 参数可根据段落情绪调整
  - 副歌: 大幅度 zoom（1.0→1.5），快速平移
  - 叙事段: 小幅度 zoom（1.0→1.2），缓慢平移
- **色彩控制**:
  - 图片 prompt 中明确色调要求（如"暖金色调"、"冷蓝色调"）
  - 渲染阶段可加 LUT 色彩滤镜（远期）

### 2.4 写实/风格自洽

| 等级 | 标准 | Erhu Agent 实现 |
|------|------|-----------------|
| **优质** | 若写实，光影质感真实；若非写实，光影质感模糊；人物动作准确 | 目标标准 |
| **普通** | 写实风格有轻微失真但不违和；人物动作准确度一般 | 当前可接受 |
| **低质** | 风格混乱，写实与非写实元素不协调 | 需避免 |

**Erhu 执行要点**:
- 二虎定位为**写实风格**，图片 prompt 中必须包含 "写实摄影风格"、"高清"、"自然光" 等关键词
- 避免在同一首 MV 中混用写实和卡通/动漫风格
- 人物形象（若使用数字人）必须符合现实物理逻辑
- 古风歌曲可使用国画风格（视为"风格化写实"而非非写实）

### 2.5 配乐质量

| 等级 | 标准 | Erhu Agent 实现 |
|------|------|-----------------|
| **优质** | 配乐音质高，旋律吸引人，音质处理令人舒适 | 目标标准 |
| **普通** | 旋律平淡或拖沓无亮点，音质处理无不适 | 当前基准 |
| **低质** | 配乐刺耳、失真、与画面脱节 | 需避免 |

**Erhu 执行要点**:
- ACE API 生成的音频为基础素材
- 输出前检查: 无爆音、无削波、音量正常
- 旋律质量依赖 lemong-agent 的 prompt 质量，需在计划文档中提供充分的音乐风格描述
- 音质处理建议（远期）: 输出前做 `loudnorm` 归一化 + 轻微压缩

### 2.6 材质表现

| 等级 | 标准 | Erhu Agent 实现 |
|------|------|-----------------|
| **优质** | 材质具有艺术处理并形成统一 | 目标标准 |
| **普通** | 材质无明显错位但普通 | 当前基准 |
| **低质** | 材质粗糙、明显 AI 痕迹 | 需避免 |

**Erhu 执行要点**:
- 图片 prompt 中明确材质要求（如"皮肤质感细腻"、"衣物纹理清晰"、"自然材质"）
- 避免使用低质量的占位图（纯色+文字）
- 图片生成失败时优先重试而非使用占位图

### 2.7 创意价值

| 等级 | 标准 | Erhu Agent 实现 |
|------|------|-----------------|
| **优质** | 审美独特，可引发视觉愉悦或思考，适合作为灵感参考 | 目标标准 |
| **普通** | 常见风格执行到位，无创新 | 当前基准 |
| **低质** | 明显抄袭、无创意、画面与歌曲无关 | 需避免 |

**Erhu 执行要点**:
- 视觉创意来源于计划文档中的"创作主题"和"歌词方向"
- 鼓励在计划文档中提出独特的视觉概念（如"水墨与实景融合"、"老照片质感"）
- 避免千篇一律的"风景+人物"模式

## 三、作品计划文档规范（增强版）

> 在原有计划文档格式基础上，增加 MV 视觉质量相关字段

```markdown
# 作品名

## 创作主题
描述歌曲的核心主题...

## 歌词方向
歌词设计的思路...

## 音乐风格
乡村民谣 / 流行 / 古风 等...

## 视觉方向（新增）
- 视觉主题: 如"旅途中的孤独与自由"、"四季流转"
- 色调倾向: 如"暖金色调"、"冷蓝色调"、"褪色胶片"
- 视觉符号: 如"反复出现的公路"、"窗外的雨"
- 参考风格: 如"王家卫式色调"、"国家地理摄影"

## 特别要求
（可选）其他特殊需求...
```

## 四、质量自检清单

> 每首 MV 生成后，应逐项自检。标记 ✅ / ⚠️ / ❌

### 基础质量

| # | 检查项 | 优质标准 | 状态 |
|---|--------|---------|------|
| 1 | 封面 | 清晰、美观，代表作品核心 | ☐ |
| 2 | 标题 | 精炼、准确、无错别字 | ☐ |
| 3 | 时长 | 16s ~ 5min（推荐 2-4min） | ☐ |
| 4 | 字幕 | 完整准确、时间轴对齐、可读 | ☐ |
| 5 | 音频 | 人声清晰、无爆音、BGM 平衡 | ☐ |
| 6 | 画质 | 1080p，画面清晰 | ☐ |
| 7 | AI 一致性 | 无明显 AI 瑕疵，主体连贯 | ☐ |

### MV 垂类质量

| # | 检查项 | 优质标准 | 状态 |
|---|--------|---------|------|
| 8 | 视觉主题统一 | 有清晰视觉符号和情绪曲线 | ☐ |
| 9 | 镜头语言 | 景别服务于音乐节奏 | ☐ |
| 10 | 光影色彩 | 有明确风格倾向，色调统一 | ☐ |
| 11 | 剪辑节奏 | 与音乐结构匹配，有变化 | ☐ |
| 12 | 写实自洽 | 风格统一，无混搭违和 | ☐ |
| 13 | 配乐质量 | 旋律吸引人，音质良好 | ☐ |
| 14 | 材质表现 | 材质有艺术处理且统一 | ☐ |
| 15 | 创意价值 | 有独特审美或表达 | ☐ |

### 技术质量

| # | 检查项 | 标准 | 状态 |
|---|--------|------|------|
| 16 | 音画同步 | 偏差 ≤ 0.5s | ☐ |
| 17 | 文件完整性 | mp3 + mp4 + 歌词 + prompt.json 齐全 | ☐ |
| 18 | 元数据 | meta.json 记录完整 | ☐ |
| 19 | 索引更新 | INDEX.md 状态已更新 | ☐ |

## 五、各阶段质量标准映射

> 将 MV 质量标准映射到 Erhu Agent 工作流的各阶段

### 5.1 compose（歌曲生成）

| 质量维度 | 检查点 | 责任人 |
|---------|--------|--------|
| 时长控制 | 120-240s 为目标区间 | lemong-agent prompt |
| 歌词准确 | 无错别字、段落标记完整 | DeepSeek 输出验证 |
| 音质 | ACE API 输出无爆音/削波 | 后置检查 |
| 音色一致 | 二虎音色模板正确注入 | compose.js |

### 5.2 visualize（图片生成）

| 质量维度 | 检查点 | 责任人 |
|---------|--------|--------|
| 图片风格统一 | 全曲使用同一 `imageStyle` | visualize.js |
| 视觉主题一致 | prompt 包含统一视觉符号 | DeepSeek prompt 设计 |
| AI 瑕疵检查 | 每张图无明显瑕疵 | 后置人工/自动检查 |
| 情绪曲线 | 图片色调/构图随段落递进 | DeepSeek prompt 设计 |
| 分辨率 | 1280×720 以上 | 生图 API 参数 |

### 5.3 render（视频合成）

| 质量维度 | 检查点 | 责任人 |
|---------|--------|--------|
| 输出分辨率 | 1920×1080 | render.js |
| 音画同步 | `-shortest` 以音频为准 | render.js |
| 剪辑节奏 | 按段落分配时长（非等分） | render.js（待优化） |
| 字幕可读 | 字号、颜色、位置、描边 | render.js |
| 编码质量 | H.264, ≥ 5Mbps | render.js |

## 六、与 LibTV 规范的差异说明

| 维度 | LibTV 通用 MV 标准 | Erhu Agent 适配 |
|------|-------------------|----------------|
| 人声/旁白 | 要求清晰无杂音 | ACE API 生成，质量取决于 AI |
| 配乐 | BGM + 人声层次分明 | 歌曲本身就是完整作品（人声+伴奏一体） |
| 写实度 | 要求符合物理逻辑 | AI 生成图片有固有局限，接受轻微瑕疵 |
| 封面 | 手动设计 | 从图片素材中自动选取 |
| 视频素材 | 实拍/AI 视频 | 当前为静图 Ken Burns，远期升级 CogVideoX |
| 剪辑 | 专业剪辑软件 | FFmpeg 自动化，创意受限 |
