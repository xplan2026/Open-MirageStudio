# Mirage-Studio 工作室定位与架构

> **最后更新**: 2026-08-09 | **版本**: 2.0
>
> 本文档是 Mirage-Studio 项目定位的单一信任源 (SSOT)。所有其他文件（README、CODEBUDDY、各 Agent AGENTS.md）中关于定位的描述，均以此文档为准。

---

## 一、顶层定位

**Mirage-Studio** 是一个**独立自媒体 IP 工作室**，以长篇连载小说《幻觉》为基石，通过多个 AI Agent 协作，持续生产跨媒介内容（小说、歌曲、MV、族谱可视化），并通过官方网站对外展示。

### 核心理念

> 《幻觉》小说是整个项目的骨架——它不一定要"完成"，而是在持续创作中变得越来越生动。补充信息越多，可供其他 Agent 创作的知识越丰富，工作室才有可持续生产的能力。

## 二、模块架构

### 2.1 核心 Agent

| Agent | 目录 | 定位 | 触发方式 |
|-------|------|------|----------|
| **Coordinator-Agent** | `coordinator-agent/` | 统一调度层，意图解析 → 任务编排 → Agent 路由 | 接收用户指令（微信 / CLI / Admin-UI） |
| **Xujie Writer Agent** | `xujie-writer-agent/` | 小说《幻觉》创作，项目基石 | 用户指令触发（手动续写、设定更新） |
| **Zhupu Manager Agent** | `zhupu-manager-agent/` | 辅助小说创作，管理角色家族关系与一致性 | 跟随小说更新触发 / 用户独立操作 |
| **Lemong Agent** | `lemong-agent/` | AI 原创歌曲创作，从小说提取灵感或独立创作 | 用户指令触发 |
| **Erhu Agent** | `erhu-agent/` | 数字人歌手"二虎"的 MV 制作 | 用户指令触发（基于已有歌曲） |

### 2.2 配套设施

| 设施 | 目录 | 定位 | 状态 |
|------|------|------|------|
| **Website** | `website/` | 「幻觉」IP 官方网站，对外展示小说/音乐/MV/族谱 | 开发中 |
| **Admin-UI** | `coordinator-agent/admin-ui/` | **工作台** — 创作指令入口 + 数据看板 + 产物管理 + AI 推广交互 | ✅ 已部署 v0.1（待升级为工作台） |
| **iLink-bot** | （通信层） | 微信集成通信通道，接收用户指令并路由到 Coordinator | 🔴 待对接 |

## 三、创作工作流

### 3.1 总览

```
用户指令（微信 / Admin-UI / CLI）
        │
        ▼
┌──────────────────────┐
│   Coordinator-Agent   │  意图解析 + 任务编排 + Agent 路由
└──────┬───────────────┘
       │
       ├──────────────► Xujie Writer Agent ────► 《幻觉》小说章节
       │                      │
       │                      ▼
       │               Zhupu Manager Agent ──► 角色族谱数据
       │
       ├──────────────► Lemong Agent ────────► 歌曲 MP3
       │                      │
       │                      ▼
       │               Erhu Agent ───────────► 数字人 MV
       │
       └──────────────► 产物索引 → Website 展示
```

### 3.2 关键约束

1. **非自动联动**：小说更新**不自动**触发歌曲/MV 创作。所有下游创作需要用户明确指令。
2. **小说是基石但不是瓶颈**：即便小说未更新，也可基于已有章节/角色独立创作歌曲和 MV。
3. **用户始终在回路中**：每个创作环节都需要用户确认或发起。

### 3.3 典型工作流示例

#### 小说创作流
```
用户指令 → Coordinator → Xujie Writer: 续写下一章
                        → 完成后: 新角色 → Zhupu Manager: 更新族谱
```

#### 从小说到歌曲流
```
用户指令 → Coordinator → Lemong: 基于《幻觉》第X章主题创作歌曲
                        → 完成后: 产物路径回写
```

#### 歌曲到 MV 流
```
用户指令 → Coordinator → Erhu: 将歌曲《XXX》升级为 MV
                        → 完成后: MV 文件路径回写
```

## 四、Admin-UI 工作台定位

Admin-UI 是工作室的**中央工作台**，不是被动监控面板。它应该具备以下能力：

### 4.1 当前已实现（v0.1）
- Dashboard：Agent 状态、任务统计、成功率
- 任务编排：自然语言创建任务
- Agent 状态监控
- 日志查看

### 4.2 待升级为工作台

| 模块 | 功能 | 优先级 |
|------|------|--------|
| **总体看板** | 增强：作品在架数量、各渠道数据、生产管线概览 | 高 |
| **创作指令中心** | 触发小说续写 / 发起歌曲创作 / 发起 MV 制作 / 族谱查询 | 最高 |
| **产物管理中心** | 歌曲/MV/章节 列表、发布状态管理、下线/上线 | 高 |
| **AI 推广交互** | 基于官网内容，对外 AI 问答（推广本项目）、社交媒体内容生成 | 中 |
| **族谱可视化** | 在线浏览族谱树、角色关系图谱 | 中 |
| **内容编排** | 从小说章节提取灵感 → 一键发起歌曲创作 → 完成后一键发起 MV | 中 |
