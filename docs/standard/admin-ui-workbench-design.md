# Admin-UI 工作台升级设计方案

> **创建日期**: 2026-08-09 | **版本**: 1.0
> **参考**: `docs/standard/mirage-studio-positioning.md`

---

## 一、定位升级

| 维度 | 旧版 (v0.1) | 新版 (v2.0) |
|------|------------|-------------|
| 品牌 | "MirageStudio Admin Console" | "MirageStudio Workbench" |
| 定位 | 数据中台 Dashboard（被动监控） | **工作台**（主动创作 + 监控 + 管理） |
| 用户 | 管理员查看状态 | 工作室运营者操作全流程 |
| 核心能力 | 看板、任务列表、日志 | 创作指令 + 产物管理 + AI 推广 + 看板 |

### 2.2 各页面详细设计

#### 总览看板 (Dashboard)

**已有**：Agent 总数/在线、任务统计、成功率、最近任务

**增强**：
- 📊 **作品在架数量**：已发布的小说章节数、歌曲数、MV 数量
- 📈 **生产管线概览**：Pipeline 视图，每个 Agent 最近一次产出状态
- 📱 **渠道数据**：官网访问量、各平台 MV 观看量（如有）
- 🔔 **待办提醒**：大纲待补、角色待建档、伏笔待回收

#### 创作中心 (Creator) — 🆕

**核心功能**：可视化触发各 Agent 创作。

**小说创作页**：
- 当前大纲总览（卷章结构树）
- 章节列表 + 状态（大纲/草稿/已发布）
- 「续写下一章」按钮 → 调用 Coordinator → Xujie Writer
- 「修改当前章」输入框
- 伏笔追踪面板（已埋 / 首现章节 / 是否回收）

**歌曲创作页**：
- 创作方式选择：
  - 「从小说提取灵感」→ 选择章节/角色/主题 → 自动提取上下文 → Lemong
  - 「自由创作」→ 描述主题和风格 → Lemong
- 歌曲列表（已创作，链接到产物管理）

**MV 制作页**：
- 已创作歌曲列表 → 选择一首 →「制作 MV」
- 视觉方向快速设置（色调、风格、主题符号）
- MV 制作进度

#### 产物管理 (Assets) — 🆕

管理所有已完成作品，控制对外展示：

- **小说章节**：章节列表、发布状态(草稿/已发布)、下线上线
- **歌曲库**：歌曲列表、可播放预览、上线/下线
- **MV 作品集**：MV 列表、可播放预览、发布平台标记(官网/抖音/视频号)

#### 族谱 (Zhupu) — 🆕

嵌入或链接到 Zhupu Manager 前端：
- 家族列表 → 选择家族 → 树形/图形可视化
- 角色关系查询
- 快速添加成员（从小说角色创建接口）

#### AI 推广 (Promotion) — 🆕

**定位**：基于官网内容，利用 AI 辅助推广 Mirage-Studio IP。

- **对外 AI 问答**：基于官网内容（小说+歌曲+MV）构建问答系统，供外部访客与 IP 互动
- **社交媒体内容生成**：基于新作品自动生成小红书/抖音/微博文案 + 封面建议
- **SEO 内容**：为官网各页面生成 SEO 描述、关键词

## 三、技术实现

### 3.1 现有技术栈

- React SPA + Vite + React Router
- API 封装 (`src/api.js`)
- 组件库：AgentCard、TaskCard、StatusBadge、Layout

### 3.2 新增依赖

| 需求 | 方案 |
|------|------|
| 音频播放 | HTML5 `<audio>` 或 react-audio-player |
| 视频播放 | HTML5 `<video>` 或 react-player |
| 族谱可视化 | 嵌入 Zhupu 的 D3/SVG 组件或 iframe |
| AI 问答 | 后端 API 新增 `/api/admin/promotion/qa` |

### 3.3 API 扩展

需要 Coordinator 后端新增以下 API：

| 端点 | 用途 |
|------|------|
| `POST /api/admin/creator/write` | 触发小说续写 |
| `POST /api/admin/creator/song` | 触发歌曲创作 |
| `POST /api/admin/creator/mv` | 触发 MV 制作 |
| `GET /api/admin/assets/chapters` | 获取章节列表 |
| `GET /api/admin/assets/songs` | 获取歌曲列表 |
| `GET /api/admin/assets/mvs` | 获取 MV 列表 |
| `PATCH /api/admin/assets/:type/:id/publish` | 上下线制品 |
| `POST /api/admin/promotion/qa` | AI 问答 |
| `POST /api/admin/promotion/social` | 社交媒体文案生成 |

## 四、分阶段实施

### Phase 1: 品牌 + Dashboard 增强（1-2 天）

- 侧边栏 Logo/标题 "MirageStudio Workbench"
- Dashboard 增加作品在架数量、管线概览

### Phase 2: 创作中心（3-5 天）

- 歌曲创作页：从小说提取灵感 + 自由创作
- MV 制作页：选择歌曲 → 触发制作

### Phase 3: 产物管理 + 族谱（2-3 天）

- 产物管理页：章节/歌曲/MV 列表 + 上下线
- 族谱页面：嵌入或链接 Zhupu

### Phase 4: AI 推广（3-5 天）

- 对外 AI 问答引擎
- 社交媒体内容生成
- SEO 内容

## 五、与 Website 的关系

| | Admin-UI (工作台) | Website (官网) |
|---|---|---|
| 用户 | 工作室运营者（内部） | 外部访客/粉丝 |
| 目录 | `coordinator-agent/admin-ui/` | `website/` |
| 功能 | 创作、管理、监控 | 展示、消费 |
| 认证 | Basic Auth | 公开 |
| 数据流 | 写入 data/ + 管理发布状态 | 从 data/ 读取已发布内容 |

两者通过 `data/` 目录 + 发布状态标记来解耦：Admin-UI 管理"是否发布"，Website 只展示"已发布"的内容。
