# Xujie Writer Agent — 长篇小说写作设计文档

> **创建日期**: 2026-08-21
> **版本**: v1.0
> **状态**: 已部署
> **定位**: 《幻觉》小说创作专用 Agent，项目基石
> **触发方式**: 用户指令触发（非自动续写）

---

## 一、定位与职责

### 1.1 核心定位

Xujie Writer Agent 是 Mirage-Studio 的**长篇小说写作专用 Agent**，是整个工作室的内容源头。《幻觉》小说是项目基石，所有其他内容（歌曲、MV、宣传）都源自小说创作。

### 1.2 核心职责

| 职责 | 说明 |
|------|------|
| **小说创作** | 从大纲细纲到成稿审校的全流程管理 |
| **角色管理** | 角色档案管理（姻亲/社会关系分类） |
| **族谱联动** | 自动触发 Zhupu Manager Agent 同步族谱 |
| **设定管理** | 世界观设定、大纲细纲、进度跟踪 |
| **人控 AI 辅助** | 由人掌控创意和决策，Agent 负责管理设定、角色状态、逻辑一致性 |

### 1.3 与其他 Agent 的关系

```
Xujie Writer Agent
    ↓ (生成新章节)
    ├─► Lemong Agent → 提取灵感创作歌曲
    ├─► Erhu Agent → 为歌曲制作 MV
    └─► Zhupu Manager Agent → 同步族谱（米家/姻亲/社会关系）
```

## 二、创作模式：镜头切换创作模式

### 2.1 核心思想

**「时间轴是经线，家族线是纬线」**：

- 全书有一条**统一时间轴**（年/月/日），所有家族事件挂靠其上
- 每个家族是一条**叙事线**（镜头），各自推进各自的动态
- 镜头在家族线之间**切换**，呈现「同一时刻，不同家族各自发生什么」
- 在家族线之外，还有一条**社会关系线**（非家族谱内的重要角色），负责把各家族勾连起来、提供外部视角

### 2.2 三条轴线

| 轴线 | 内容 | 功能 |
|------|------|------|
| **家族线**（每个家族一条） | 该家族在时间轴上的动态：事件、人物成长、家族兴衰 | 主干叙事 |
| **社会关系线** | 家族谱外的重要角色（挚友/恩人/对手/见证者等）的视角与行动 | 勾连家族、外部视角、独立支线 |
| **时间轴** | 全书统一纪年，所有事件精确挂靠日期 | 经线，保证多线同步 |

### 2.3 镜头切换类型

| 切换类型 | 说明 | 示例 |
|---------|------|------|
| **并行切换** | 同一时刻，从 A 家族切到 B 家族（A 事件与 B 事件同时发生） | 米家张罗分家时，李家正在讨债 |
| **因果切换** | A 线的行动导致 B 线的反应 | 米家逃债 → 田维城连夜转移米南生 |
| **呼应切换** | A 线设置的信息/情感，在 B 线得到呼应 | 米南生入伍，李家儿子同日回城 |
| **悬念切换** | A 线留悬念 → 切 B 线 → 稍后回 A 线揭晓 | 米福云失踪 → 切李家线 → 再回揭示去向 |

### 2.4 镜头切换节奏

| 范围 | 切换频度 | 原则 |
|------|---------|------|
| 单章 | 2~4 个镜头 | 每镜头约 800-1500 字，形成"短镜头快切"节奏 |
| 单卷 | 每 3-5 章至少覆盖 1 条新的家族线 | 保证多家族都有戏份 |
| 全书 | 各家族线按卷推进 | 遵循族谱关系网与跨家族联姻图 |

## 四、写作流程

### 4.1 创作准备阶段

#### 4.1.1 建立大纲

```markdown
## 第 {N} 章：{章标题}（{故事日期范围}）

- **镜头序列**：{米家线 → 李家线 → 社会关系线}
- **时间对齐**：{本章所有镜头发生在同一时间跨度内，标注起点-终点}
- **POV**：{主镜头视角}
- **标签**：【{线A}】【镜头切换】【爽点】【钩子】

#### 镜头 1（米家线）{时间：HH:MM-HH:MM}
- {该家族本章动态：事件/冲突/转折}
- 出场角色：{角色列表}

#### 镜头 2（李家线）{时间：HH:MM-HH:MM}
- {该家族本章动态}
- 出场角色：{角色列表}

#### 镜头 3（社会关系线）{时间：HH:MM-HH:MM}
- {重要角色本章行动}
- 出场角色：{角色列表}
```

#### 4.1.2 建立时间轴对齐表

```markdown
| 时间 | 米家线 | 李家线 | 杨家线 | 何家线 | 于家线 | 社会关系线 |
|------|--------|--------|--------|--------|--------|-----------|
| 1916-03 | 分家被算 | 当铺扩张 | （未登场） | （未登场） | （未登场） | 田维城入川 |
| 1944-06 | 米湘逃债 | 收米家铺子 | （未登场） | （未登场） | （未登场） | 地下党接应 |
| 1961-09 | 南生参军 | 李维贞续弦 | 杨常玉归川 | （未登场） | （未登场） | 曾绾销声匿迹 |
```

**规则**：同一时间点，最多 3 条线同时推进；未登场的家族线在表中标注"未登场"。

### 4.2 正文写作阶段

#### 4.2.1 镜头标记

细纲与正文中，每个镜头（场景群）需标记所属线：

```markdown
## 场景列表

1. **场景1（米家线）**：{场景名称}
2. **场景2（李家线）**：{场景名称}
3. **场景3（社会关系线）**：{场景名称}
```

正文 HTML 注释同步标注镜头归属：

```markdown
<!-- LOGIC: time=1916-03-15 09:15 | loc=米家大宅 | line=米家线 | present=米福云,米湘 -->
<!-- LOGIC: time=1916-03-15 09:15 | loc=李记当铺 | line=李家线 | present=李维贞之父 -->
```

#### 4.2.2 写作要点

1. **时间必须对齐**：同一章内所有镜头时间跨度一致，切换时标注时间，严禁时间倒流
2. **切换要留衔接**：每个镜头结尾留"切点"（悬念/因果/呼应），保证镜头间逻辑连贯
3. **每镜头一个焦点**：单镜头内只推进一个家族（或一个社会关系角色）的核心事件
4. **家族线均衡**：避免连续 3 章只推一条线；未登场家族在时间轴对齐表中标注
5. **社会关系线节奏**：社会关系角色按需出场，不是每章都在

### 4.3 角色档案管理

#### 4.3.1 分类存放

```
characters/
├── 姻亲/          # ★ 各家族谱内人物（有族谱归属）
│   ├── {家族A}/{角色名}.md 或 {角色名}.md
│   └── ...
├── 社会关系/      # ★ 家族谱外的重要角色
│   ├── 模板.md
│   └── {角色名}.md
└── README.md
```

#### 4.3.2 分类判定

| 类别 | 判定 | 档案目录 |
|------|------|---------|
| 姻亲 | 能在某个家族族谱中找到关系节点 | `characters/姻亲/` |
| 社会关系 | 不在任何家族谱内，但重要且与多家族叙事相关 | `characters/社会关系/` |

#### 4.3.3 社会关系角色档案必含字段

参照 `characters/社会关系/模板.md`，核心字段：

- 身份定位（一句话）
- **与各家族的关系表**（米家/李家/杨家/何家/于家各自的关系与关键事件）
- 人物背景、性格、说话风格
- 关键场景（含叙事意义）
- **在小说中的功能**（叙事/多家族联动/主题/情感）
- 与主线的关系弧线（按年代）

### 4.4 族谱联动

#### 4.4.1 自动触发机制

当小说章节完成时，自动解析新章节中出现的新角色：

```javascript
// 伪代码
const newCharacters = extractCharacters(chapter);
if (newCharacters.length > 0) {
  await zhupuManager.update(newCharacters);
}
```

#### 4.4.2 联动内容

- 姻亲角色：更新对应家族的族谱（`data/Zhupu-data/{家族名}/族谱.json`）
- 社会关系角色：更新社会关系档案（`characters/社会关系/`）
- 关联更新：跨家族联姻图（`data/Zhupu-data/graph/跨家族联姻图.json`）

## 五、作品结构（以《幻觉》为例）

### 5.1 四卷结构

| 卷 | 暂名 | 年代 | 核心人物 | 叙事方式 |
|----|------|------|---------|---------|
| 一 | 潼南旧事 | 1914-1961 | 米福云→米南生 | 多重口述 + 想象重构 |
| 二 | 子弟 | 1961-1979 | 米南生→米丰 | 米南生主POV，米丰辅 |
| 三 | 激荡 | 1979-2009 | 米丰 | 米丰主POV |
| 四 | 幻觉 | 2009-2023 | 米丰 | 米丰主POV |

### 5.2 立意

> 人们一生所信奉的"知识"，有多少不过是时代的幻觉？

### 5.3 主角

**米丰**（1973年生），四代家族命运的主线人物。

## 六、技术实现

### 6.1 CLI 入口

```bash
# 小说续写
xujie-writer write --chapter "第11章" --family "米家" --previous "第10章"

# 大纲生成
xujie-writer outline --chapter "第11章" --timeline "1944-06"

# 角色查询
xujie-writer character --name "米丰"

# 族谱联动
xujie-writer sync-zhupu --chapter "第11章"
```

### 6.2 环境变量

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `XUJIE_DATA_DIR` | 数据目录路径 | `data/XujieWriter-data` |
| `XUJIE_LLM_MODEL` | LLM 模型名称 | DeepSeek |
| `XUJIE_LLM_API_KEY` | LLM API Key | — |

### 6.3 GLOSSARY（Token 优化术语表）

`GLOSSARY.md` 定义了项目专用的术语和缩写，用于优化 Token 使用：

| 术语 | 全称 | 用途 |
|------|------|------|
| [米家] | 米家 | 主家族 |
| [李家] | 李家 | 对立家族 |
| [切点] | 镜头切换点 | 镜头切换处 |

## 七、与其他 Agent 的集成

### 7.1 Coordinator-Agent 调用

```javascript
// Coordinator Agent 调用示例
POST /api/workbench/creator/write
{
  "chapter": "第11章",
  "context": {
    "family": "米家",
    "previousChapter": "第10章"
  }
}
```

### 7.2 Lemong Agent 联动

当需要从小说提取灵感创作歌曲时：

```javascript
// 1. 提取章节内容
const chapterContent = await xujie.getChapter("第10章");

// 2. 生成创作背景
const inspiration = await extractInspiration(chapterContent);

// 3. 调用 Lemong Agent
await lemong.createSong(inspiration);
```

### 7.3 Zhupu Manager Agent 联动

当章节中出现新角色时：

```javascript
// 1. 解析新角色
const newCharacters = await extractNewCharacters(chapter);

// 2. 分类（姻亲/社会关系）
const categorized = categorizeCharacters(newCharacters);

// 3. 更新族谱
await zhupu.update(categorized);
```

## 八、设计理念

### 8.1 人控 AI 辅助

Xujie Writer Agent 遵循"人控 AI 辅助"理念：

| 职责 | 人类 | Agent |
|------|------|-------|
| **创意决策** | ✓ | — |
| **情节走向** | ✓ | — |
| **角色设定** | ✓ | — |
| **设定管理** | — | ✓ |
| **角色状态** | — | ✓ |
| **逻辑一致性** | — | ✓ |

### 8.2 镜头切换模式的升级

镜头切换模式是既有多线结构 + 多线切换技巧的**升级具体化**：

| 既有规范 | 镜头切换模式 |
|---------|-------------|
| 多线结构（A线/B线） | 家族线（每家族一线）+ 社会关系线 |
| 时间同步切换 | 必须有时间轴对齐表支撑 |
| 因果切换 / 悬念切换 | 家族间因果、悬念切换（跨家族联动） |
| 交织规则 | 镜头切换节奏（单章 2-4 镜头） |
