# 博客模块设计与实施

> **创建日期**: 2026-08-11 | **版本**: v1.0
>
> 本文档记录 Mirage-Studio 网站博客模块的技术架构、设计决策与实施细节，是博客模块的单一信任源 (SSOT)。

---

## 一、模块定位

### 1.1 定位

博客是 Mirage-Studio 网站的独立子模块，聚焦**项目开发与维护中的创新实践和实现思路**。以图文形式、Markdown 格式记录技术经验。

### 1.2 核心约束

| 约束 | 说明 |
|------|------|
| 非自动创作 | 由用户不定期通过 AI 辅助创作，无固定发布计划 |
| 与小说无关 | 博客内容与《幻觉》小说完全独立，互相无关联 |
| 非新闻/日誌 | 不记录日常进度，聚焦技术深度与复用价值 |

### 1.3 涉及范围

| 方向 | 示例 |
|------|------|
| 项目定位/目标/规划 | 工作室架构演进、技术路线选择 |
| Agent 设计目的与方案 | 各 Agent 的设计思想、技术方案拆解 |
| 子模块复用价值 | 可独立使用工具/方案的技术分享 |
| 前沿技术可行性分析 | 新 API、新框架在项目中的引入评估 |
| Agent 协作流程 | 多 Agent 任务编排的实践与经验 |

## 二、架构设计

### 2.1 数据流

```
用户创作 (AI 辅助)
    │
    ▼
data/blog-posts/{序号}-{slug}.md       ← Markdown 源文件 + YAML frontmatter
    │
    ▼  (git push → GitHub → 服务器 git pull)
    │
website/src/lib/data.ts                ← parseFrontmatter() 解析 frontmatter + 正文
    │
    ▼  (npm run build)
    │
website/src/pages/blog/index.astro      ← 列表页 (getBlogPosts)
website/src/pages/blog/[...slug].astro  ← 详情页 (getBlogPost + marked 渲染)
    │
    ▼  (static SSG)
    │
website/dist/blog/                      ← 静态 HTML 产物
    │
    ▼  (rsync to /opt/mirage-studio/website/dist/)
    │
Nginx → HTTP 200                        ← IP 直连 + Cloudflare Pages 代理
```

### 2.2 存储决策：`data/blog-posts/`

**最终选择**: `data/blog-posts/`，而非 `docs/blog-posts/`。

| 维度 | `data/` ✅ | `docs/` ❌ |
|------|-----------|-----------|
| 语义匹配 | 博客是对外发布的"内容产品" | docs 是项目规范 SSOT |
| 架构一致性 | Website 统一从 `data/` 读取展示数据 | docs 不被 website 消费 |
| 职责分离 | 博客可从 docs 取材，但不与 SSOT 混放 | 保持 docs 纯粹性 |

**结论**: 博客本质是对外内容产品（与小说/歌曲/MV 同类），应归属 `data/`。`docs/` 保持"开发者规范 SSOT"的纯粹定位。

## 四、数据类型

### 4.1 BlogPost 接口

```typescript
// website/src/lib/types.ts
export interface BlogPost {
  slug: string;         // "01-mirage-studio-architecture"（不含 .md）
  title: string;        // 文章标题（从 frontmatter 解析）
  date: string;         // 发布日期 "YYYY-MM-DD"
  summary: string;      // 一句话摘要
  tags: string[];       // 标签列表
  content: string;      // Markdown 正文（不含 frontmatter 块）
}
```

### 4.2 数据读取函数

```typescript
// website/src/lib/data.ts
getBlogPosts(): BlogPost[]     // 按日期倒序返回所有文章
getBlogPost(slug): BlogPost    // 返回指定 slug 的文章
parseFrontmatter(raw): { meta, body }  // YAML frontmatter 解析器
```

### 4.3 Frontmatter 格式

每篇文章 `.md` 文件头部：

```yaml
---
title: "AI 数字人 MV 零成本制作全流程：Erhu Agent 设计揭秘"
date: "2026-08-10"
summary: "从歌词到 MV，只用免费 API 和 FFmpeg 完成一部完整的 AI 音乐视频。"
tags: ["AI音乐", "MV制作", "Agent设计", "零成本"]
---
```

## 五、页面设计

### 5.1 博客列表页 `/blog`

- **布局**: 单列、最大宽度 3xl、自上而下排列
- **每篇文章卡片**: 标题 → 日期 + 标签 → 摘要 → 「阅读全文 →」链接
- **分隔**: `border-b` 分隔各文章
- **空状态**: "暂无文章" 居中提示
- **风格**: 与网站一致的 literary minimalism（Noto Serif SC + 金色 accent）

### 5.2 博客详情页 `/blog/{slug}`

- **顶部**: 「← 博客列表」返回链接
- **头部**: 文章标题 + 日期 + 标签徽章（`border-b` 分隔）
- **正文**: `marked` 库渲染 Markdown → HTML，搭配 Tailwind `prose` 排版
- **底部**: 分隔线 + 返回链接
- **路由**: Astro `getStaticPaths` + `[...slug].astro` 动态路由
- **404 处理**: 不存在 slug → `Astro.redirect('/blog')`

### 5.3 首页博客入口

```astro
<a href="/blog" class="group block p-6 border ...">
  <h3>博客</h3>
  <p>技术实践，架构思考</p>
  <span>{blogPosts.length} 篇文章</span>
</a>
```

### 5.4 导航

```typescript
{ href: '/blog', label: '博客' }  // 插入在「族谱」与「社区」之间
```

## 六、Markdown 渲染

### 6.1 选型：marked

| 方案 | 优点 | 缺点 |
|------|------|------|
| **marked** ✅ | 轻量（~50KB）、零配置、GFM 支持 | 功能不如 unified 丰富 |
| Astro Content Collections | 原生集成 | 需要 `.md` 文件在 `src/content/` 下，不符合现有 data/ 架构 |
| unified + remark | 插件生态丰富 | 重、配置复杂 |

**选择 marked 的原因**：
1. 博客文章不需要复杂的内容转换
2. 源文件在 `data/blog-posts/`（非 `src/`），Astro Content Collections 不适用
3. 与现有的 `data.ts` 统一读取模式兼容

### 6.2 配置

```typescript
marked.setOptions({
  gfm: true,    // GitHub Flavored Markdown（表格、删除线等）
  breaks: true, // 换行即 <br>
});
```

### 6.3 样式

使用 Tailwind `prose` 类 + 自定义 `blog-content` 覆盖，确保中文字体、颜色与网站主题一致：

```css
blog-content prose-slate max-w-none
  prose-headings:text-ink prose-headings:font-bold
  prose-h2:text-2xl prose-h2:mt-10 prose-h2:mb-4
  prose-p:text-muted prose-p:leading-relaxed
  prose-a:text-accent hover:prose-a:underline
  prose-code:text-sm prose-code:bg-paper-dark prose-code:px-1.5 prose-code:rounded
  prose-pre:bg-paper-dark prose-pre:border
  prose-blockquote:border-accent
  ...
```

## 七、部署流程

```
本地                              4C4G 服务器 (182.254.180.26)
────                              ──────────────────────────────

[1] 创作文章
    data/blog-posts/*.md

[2] git push → GitHub
    
[3] 服务器 git pull
    /opt/mirage-studio/data/blog-posts/*.md

[4] cd website && npm run build
    dist/blog/*.html

[5] rsync dist/ → /opt/mirage-studio/website/dist/

[6] sudo systemctl reload nginx
```

### Nginx 配置（已有，无需修改）

博客页面由兜底 server（`listen 80 default_server`）处理：

```nginx
root /opt/mirage-studio/website/dist;
location / { try_files $uri $uri/ /index.html; }
```

博客 CSS/JS 静态资源由缓存规则自动处理：
```nginx
location ~* \.(css|js|svg|woff2|ico|avif)$ { expires 30d; }
```

## 八、创作工具

### 8.1 脚手架脚本

```bash
# 创建新文章（自动编号、日期、frontmatter 模板）
bash coordinator-agent/scripts/new-blog-post.sh "文章标题" "标签1,标签2"
```

**行为**:
1. 扫描 `data/blog-posts/` 获取最大序号，自动递增
2. 将标题转换为英文 slug（iconv 音译）
3. 创建带 YAML frontmatter + 正文占位模板的 `.md` 文件

### 8.2 创作指南

`coordinator-agent/blog-creation-guide.md` 包含完整指引：
- 选题来源
- 文章格式规范
- 创作流程（选题 → 起草 → 写作 → 发布）
- 索引维护
- 写作原则
