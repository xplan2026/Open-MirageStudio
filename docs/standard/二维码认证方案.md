# 二维码认证方案

> **创建日期**: 2026-08-11 | **版本**: 1.0
> **适用场景**: Admin-UI 工作台登录认证，替代微信开放平台 OAuth
> **目标**: 仅允许单人（工作室运营者）通过扫码登录工作台

---

## 一、方案选型

### 1.1 为什么不用微信开放平台

微信开放平台网站应用审核周期长、要求苛刻。本项目是个人工作室内部管理工具，只需单人认证，不需面向公众的社交登录能力。

### 1.2 自建方案优势

| 维度 | 微信开放平台 OAuth | 自建 QR + JWT |
|------|-------------------|---------------|
| 外部依赖 | 需要 AppID + AppSecret | 零外部依赖 |
| 注册审核 | 1-4 周 | 无需审核 |
| 唯一性保障 | OpenID 绑定 | 物理邻近 + token 时效 |
| 用户体验 | 微信扫码 → 授权页面 → 确认 | 微信扫一扫 → 即登录 |
| 技术复杂度 | OAuth2 授权码流程 | 50 行后端 + 50 行前端 |

## 二、认证流程

### 2.1 首次登录（管理员绑定）

```
浏览器访问 https://a-o-c.cc.cd:5656/
    │
    ▼
GET /auth/qrcode → 后端返回 { token, qrcode(Data URL) }
    │                 ┌─ token: 随机 32 位 (60s 过期)
    │                 └─ qrcode: base64 PNG, 内容 = https://a-o-c.cc.cd:5656/auth/callback?token=xxx
    │
    ▼
前端显示 QR 码 + 开始轮询 GET /auth/status?token=xxx
    │
    ▼ (运营者掏出手机，微信扫一扫)
扫码打开 https://a-o-c.cc.cd:5656/auth/callback?token=xxx
    │
    ▼
后端校验 token 有效性：
  - token 未过期 ✅
  - token 未被使用 ✅
  - 将 token 标记为 "已确认"
  - 返回「登录成功」页面
    │
    ▼
浏览器轮询 GET /auth/status?token=xxx → 返回 { status: "confirmed", jwt }
    │
    ▼
前端将 jwt 存入 localStorage
后续所有 /admin/* 请求携带 Authorization: Bearer <jwt>
```

### 2.2 后续登录

与首次登录完全一致 — 每次都生成新 QR 码 + 新 token + 新 JWT。

> **设计决策**：不持久化登录状态。每次关闭浏览器后重新扫码，token 60 秒过期。简单且安全，因为运营者始终坐在电脑前。

## 三、API 设计

### 3.1 GET /auth/qrcode

生成一次性登录 token 和 QR 码。

**请求**:
```
GET /auth/qrcode
```

**响应**:
```json
{
  "token": "a1b2c3...012",
  "qrcode": "data:image/png;base64,iVBOR...",
  "expiresIn": 60
}
```

**后端逻辑**:
1. 生成 32 位随机 token (`crypto.randomBytes(16).toString('hex')`)
2. 将 token 存入内存 Map：`{ confirmed: false, createdAt: Date.now() }`
3. QR 码内容：`https://a-o-c.cc.cd:5656/auth/callback?token=${token}`
4. 调用 `qrcode` 库生成 Data URL
5. 返回 token + qrcode

### 3.2 GET /auth/callback

手机扫码后的回调（网页端点）。

**请求**:
```
GET /auth/callback?token=a1b2c3...012
```

**响应**: HTML 页面（非 JSON）

**后端逻辑**:
1. 校验 token 存在且未过期（60s）
2. 校验未被使用（`confirmed === false`）
3. 设置 `confirmed = true`
4. 返回 HTML：「登录成功，请返回电脑继续操作」

### 3.3 GET /auth/status

前端轮询登录状态。

**请求**:
```
GET /auth/status?token=a1b2c3...012
```

**响应** (未扫码):
```json
{ "status": "pending" }
```

**响应** (已扫码确认):
```json
{
  "status": "confirmed",
  "jwt": "eyJhbGciOiJIUzI1NiIs..."
}
```

**响应** (已过期):
```json
{ "status": "expired" }
```

### 3.4 JWT 结构

```json
{
  "sub": "admin",
  "role": "operator",
  "iat": 1755478000,
  "exp": 1755564400
}
```

- `sub`: 固定 `"admin"`（单用户，无需区分）
- `role`: `"operator"`（预留未来扩展：operator / viewer）
- `exp`: 签发时间 + 24 小时

## 四、JWT 密钥管理

### 4.1 首次启动自动生成

```javascript
// coordinator-agent/src/auth/jwtSecret.js
const fs = require('fs');
const path = require('path');
const crypto = require('crypto');

const SECRET_FILE = path.join(__dirname, '../../.jwt_secret');

function getJwtSecret() {
  if (fs.existsSync(SECRET_FILE)) {
    return fs.readFileSync(SECRET_FILE, 'utf8').trim();
  }
  const secret = crypto.randomBytes(32).toString('hex');
  fs.writeFileSync(SECRET_FILE, secret, { mode: 0o600 });
  return secret;
}

module.exports = { getJwtSecret };
```

- `.jwt_secret` 文件不在 Git 中（加入 `.gitignore`）
- 每次服务重启，密钥不变
- 服务器部署时，密钥文件存于 `/opt/mirage-studio/coordinator-agent/.jwt_secret`
- 权限 600，仅进程用户可读

### 4.2 轮换

如需使所有 JWT 失效，删除 `.jwt_secret` 文件后重启服务。

## 五、中间件改造

### 5.1 旧：Basic Auth (`auth.js`)

```javascript
// 旧逻辑
const auth = basicAuth({ users: { admin: process.env.ADMIN_PASSWORD } });
```

### 5.2 新：JWT Auth

```javascript
// coordinator-agent/src/middleware/auth.js
const jwt = require('jsonwebtoken');
const { getJwtSecret } = require('../auth/jwtSecret');

function jwtAuth(req, res, next) {
  const header = req.headers.authorization;
  if (!header || !header.startsWith('Bearer ')) {
    return res.status(401).json({ error: 'Unauthorized' });
  }

  const token = header.substring(7);
  try {
    const payload = jwt.verify(token, getJwtSecret());
    req.user = payload;
    next();
  } catch (err) {
    return res.status(401).json({ error: 'Token expired or invalid' });
  }
}
```

### 5.3 路由保护

```javascript
// coordinator-agent/src/index.js
app.use('/admin', jwtAuth);   // 管理 API 需要认证
app.use('/workbench', express.static(...)); // 静态文件公开
app.use('/auth', authRoutes); // 认证路由公开
app.use('/a2a', a2aRoutes);   // A2A 接口公开（或保留独立认证）
```

## 六、安全分析

| 威胁 | 缓解措施 |
|------|----------|
| token 被截获 | 60s 过期；HTTPS 传输加密 |
| token 重放 | 一次使用后标记 `confirmed`，不可复用 |
| JWT 泄露 | 24h 过期；秘钥 600 权限 |
| CSRF（扫码回调） | GET 幂等，无副作用；仅改内存状态 |
| 非运营者扫码 | 物理邻近性保证 — 必须能看到屏幕上的 QR 码 |
| 暴力破解 token | 32 位随机 hex = 128 位熵，60s 窗口内不可能 |
| 服务重启后 token 失效 | 可接受 — token 存内存，重启后重新扫码即可 |

## 七、前端改造

### 7.1 Login.jsx 核心逻辑

```jsx
function LoginPage() {
  const [qrCode, setQrCode] = useState(null);
  const [token, setToken] = useState(null);
  const [status, setStatus] = useState('idle'); // idle | waiting | expired

  const startLogin = async () => {
    const res = await fetch('/auth/qrcode');
    const data = await res.json();
    setToken(data.token);
    setQrCode(data.qrcode);
    setStatus('waiting');
    pollStatus(data.token);
  };

  const pollStatus = (t) => {
    const timer = setInterval(async () => {
      const res = await fetch(`/auth/status?token=${t}`);
      const data = await res.json();
      if (data.status === 'confirmed') {
        localStorage.setItem('jwt', data.jwt);
        clearInterval(timer);
        window.location.href = '/workbench/';
      } else if (data.status === 'expired') {
        setStatus('expired');
        clearInterval(timer);
      }
    }, 2000);
  };

  // useEffect 自动触发 startLogin...
}
```

### 7.2 api.js — 请求拦截器

```javascript
// 所有 /admin/* 请求自动携带 JWT
const apiClient = {
  async request(endpoint, options = {}) {
    const jwt = localStorage.getItem('jwt');
    const headers = { ...options.headers };
    if (jwt) {
      headers['Authorization'] = `Bearer ${jwt}`;
    }
    const res = await fetch(`/admin${endpoint}`, { ...options, headers });
    if (res.status === 401) {
      localStorage.removeItem('jwt');
      window.location.href = '/workbench/';
      return null;
    }
    return res.json();
  }
};
```
