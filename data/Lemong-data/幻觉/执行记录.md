## v2 核心改动与原因

### 问题（v1 失败原因）

v1 生成的两首歌（归航109 + 幻觉）均出现同样问题：
1. **旋律与歌词断句不匹配** — 歌曲的旋律节奏与中文歌词的自然断句/呼吸点对不上
2. **开头唱英语** — 歌曲前两句出现英语演唱，而非全程中文

### 根因分析

v1 的 music_prompt 中包含了对旋律的具体约束（BPM、调式、和弦走向等），ACE 模型在生成时会优先满足这些音乐参数约束，导致：
- 旋律被固定的 BPM 和和弦走向"框死"，无法灵活适配中文歌词的自然节奏
- 模型可能将约束解读为"西式歌曲结构"，从而产出英语开头

### v2 改动

| 改动项 | v1（失败） | v2（修正） |
|--------|-----------|-----------|
| BPM | 指定 70 | 不指定 |
| 调式 | 指定 Am | 不指定 |
| 和弦走向 | 指定 Am-G-F-E7 | 不指定 |
| 旋律描述 | 无特殊说明 | "melody must follow natural cadence of Chinese lyrics" |
| 语言强调 | 仅 caption 中提及 | caption + vocal_style + special_notes 三处强调 Chinese (Mandarin) |
| 断句指导 | 无 | "Do NOT force a fixed tempo — let vocal phrasing breathe naturally with the text" |

**核心原则**: 不约束旋律参数 → ACE 自动根据歌词文本的语音特征生成匹配的旋律。

## 执行过程 — 踩坑记录

### 失败方式

| 序号 | 方式 | 失败原因 |
|------|------|---------|
| 1 | `python3 /tmp/generate_幻觉_v2.py` | shell 环境中 **没有 Python**（仅 Node.js 可用） |
| 2 | `node generate-music.js > /tmp/output.json` | shell 的 **stdout 重定向不可靠**，输出文件无法写入 |
| 3 | `curl -o /tmp/response.json` | `/tmp` 对 shell 子进程 **不可写** |
| 4 | `node gen_v2_final.js`（前台同步执行） | `execute_command` 返回后 **Node 进程被杀**，HTTP 异步回调无法触发 |
| 5 | 内联 Node.js 代码 | 命令太长，shell 解析失败 |

### 成功方式

| 序号 | 方式 | 关键点 |
|------|------|--------|
| ✅ | `node gen_v2_fast.js &` 后台运行 | **唯一有效方案** |

**成功方案详细说明**：
1. 用 `write_to_file` 写入 Node.js 脚本（`/workspace/gen_v2_fast.js`）
2. 脚本逻辑：
   - 读取 `/tmp/幻觉_music_prompt_v2.json` + `/workspace/data/Lemong-data/幻觉/歌词.md`
   - 拼接 prompt 文本（caption + lyrics + vocal_style + special_notes）
   - 用 Node.js `https` 模块直接调用 ACE API（`api.acemusic.ai/v1/chat/completions`）
   - 超时设置 360 秒（6分钟），足够处理长中文歌词
   - 收到响应后解析 base64 音频，写入 `/data/Lemong-data/幻觉/`（该路径已验证可写）
   - 同时写入状态文件（`_v2b_started.txt` → `_v2b_done.txt`）
3. 用 `node gen_v2_fast.js &` **后台启动**，进程在 `execute_command` 返回后继续运行
4. 等待 ~4 分钟后检查 `/data/Lemong-data/幻觉/` 目录，文件已生成

### 经验教训

1. **永远先检查可用运行时**: `which python node` — 本环境只有 Node.js
2. **不要依赖 shell 重定向**: `> /tmp/file` 可能因权限问题失败，用 Node.js `fs.writeFileSync` 直接写文件
3. **异步 HTTP 调用必须用后台进程**: `execute_command` 返回时前台进程被终止，异步回调丢失
4. **文件写入目标**: `/data/Lemong-data/` 已验证可写，`/tmp/` 不可靠
5. **ACE API 超时设置**: 中文长歌词需至少 360 秒超时，实际耗时约 3-4 分钟

## v3 发现：歌词被 ACE LM 重写为英文

> 测试时间: 2026-07-15T14:27:00Z

### 问题

v2 生成的 mp3 **仍然是纯英文**，歌词与我们的中文原文毫无关系。

### 根因分析

ACE Step1.5 的 LM（语言模型）具有 **Query Rewriting（查询重写）** 功能。当歌词混在 `content` 文本中传递时，LM 会将其视为"创作建议"而非"必须执行的指令"，导致：

1. 将中文歌词翻译成英文
2. 或完全重写成另一套歌词

v3 测试中，ACE 实际生成的英文歌词：

```
[Intro: Female Vocal]
The instrumental song, you see
For I have to see a you

[Verse 1: Male Vocal]
I want to see a people I feel
I love to日本 land
The prairie where I can run away
But I'm so tired of this place

[Chorus: Female Vocal]
Go far away from the prairie
Run and run and run and jump and run and jump
```

与我们提供的"课本的页码被风撕碎..."（草原诗 / 知识觉醒主题）**完全不同**。

API 返回的元数据也证实了这一点：
```
Language: en
Caption: A blend of traditional Chinese folk and modern pop-rap...
```

### 解决方案

将 `lyrics` 作为 **API 请求的顶层独立字段**传递，而非混在 `content` 文本中：

```javascript
// ❌ 错误（v1/v2 的做法）
const body = {
  messages: [{ content: 'Generate music: ...\nLyrics:\n中文歌词...' }]
};

// ✅ 正确（v3+ 修复）
const body = {
  messages: [{ content: 'Generate music: 风格描述...' }],
  lyrics: '中文歌词...',        // 独立字段，不会被 LM 重写
  vocal_language: 'zh'          // 独立字段
};
```

### 影响

- `generate-music.js` 已更新：`lyrics` 和 `vocal_language` 作为顶层字段传递
- 知识库已更新：`中文歌曲ACE生成最佳实践.md` 新增歌词传递方式说明
