# AI 数字人 MV 零成本制作全流程：Erhu Agent 设计揭秘

## "二虎"是谁？

"二虎"（Erhu）是 Mirage-Studio 的 AI 数字人歌手 IP。音色设计为沙哑随性、鼻音重的 Eagles 风格男声——区别于主流的"完美"AI 声音，追求一种粗粝、真实的质感。

为什么叫"二虎"？因为这个项目是工作室的"第二只老虎"——第一只是小说，第二只就是音乐。同时也暗合"二胡"的发音，有一种中国式的粗犷感。

## 核心挑战

做 AI MV 面临几个现实问题：

- **预算为零**：不能使用付费 API
- **没有视频生成能力**：可灵、通义万相的视频生成需要付费
- **声音一致性**：ACE API 不支持 voice clone

那怎么办？答案是：**Ken Burns 效果 + 固定音色 prompt + 全免费 API**。

## 四阶段流水线

```
管理员投放计划文档
    ↓
[1] scan    → 扫描索引 → 找到未处理计划
    ↓
[2] compose → 调用 lemong-agent 生成歌曲（注入二虎音色）
    ↓
[3] visualize → 分析歌词 → DeepSeek 生成图片 prompt → 百度文心一格生图
    ↓
[4] render  → FFmpeg Ken Burns 静图转视频 → 拼接 → 叠加音频+字幕
    ↓
输出 → data/Erhu-data/{作品名}/{作品名}.mp4
```

### Phase 1: scan（计划扫描）

没什么花哨的——就是读取 `plans/` 目录下的计划文档，解析 `INDEX.md` 索引表，找出待处理的作品。

每个计划文档长这样：

```markdown
# 作品名

## 创作主题
描述歌曲的核心主题...

## 歌词方向
歌词设计的思路...

## 音乐风格
乡村民谣 / 流行 / 古风 等...
```

### Phase 2: compose（歌曲生成）

这个阶段依赖 lemong-agent 的两步流程：

1. DeepSeek 根据创作背景生成歌词和音乐 prompt
2. ACE API 根据 prompt 生成音频

关键创新点是**音色模板注入**：

```json
{
  "vocal_style": "Warm, gritty, nasal male vocal with a natural, unpolished delivery...",
  "special_notes": "CRITICAL: Chinese (Mandarin) song, no English lyrics..."
}
```

这套 prompt 模板确保每次生成的歌曲都保持"二虎"的辨识度。

### Phase 3: visualize（图片生成）

这是整个流程中最关键也最容易翻车的环节。

**流程**：歌词解析 → DeepSeek 生成图片 prompt → 百度文心一格生图

**歌词结构解析**：用正则匹配 `[Verse]` / `[Chorus]` 等段落标记，每段独立传递给 DeepSeek。

**图片风格映射**是一个有趣的实践：

| 歌曲风格 | 图片风格 |
|---------|---------|
| 乡村 / 民谣 | 写实 |
| 古风 | 国画 |
| 流行 | 插画 |
| 电子 | 3D |

一张 3 分钟的歌曲大约需要 34 张图片（歌词段落数 × 每段生成 6 张选 1-2 张）。

文心一格的免费额度刚好能覆盖这个需求。

### Phase 4: render（视频合成）

这是"零成本"的关键——不用 AI 视频生成，用 FFmpeg 的 Ken Burns 效果。

**什么是 Ken Burns 效果？** 简单说就是给静态图片加上缓慢的缩放和平移，制造动态感。纪录片常用这种手法。

核心参数：
- `zoompan` 滤镜：1.0→1.3 缩放 + 左右平移
- 帧率：25fps
- 编码：H.264，preset fast
- 分辨率：1920×1080

**字幕渲染**同步进行：`drawtext` 滤镜，逐句 `enable='between(t,start,end)'`，白字黑描边，底部居中。

最后拼接所有片段 + 叠加音频，输出完整 MP4。

## 成本：零元

| 环节 | API 调用 | 成本 |
|------|---------|------|
| 歌词+prompt 生成 | 1 次 DeepSeek | ¥0 |
| 音乐生成 | 1 次 ACE | ¥0 |
| 图片 prompt | 1 次 DeepSeek | ¥0 |
| 图片生成 | ~34 次文心一格 | ¥0 |
| 视频合成 | FFmpeg 本地 | ¥0 |
| **合计** | — | **¥0** |

> 免费额度有上限，批量生产时需要关注配额。但作为一个个人创作者，目前的额度完全够用。

## 技术决策中的取舍

这个项目中有几个值得分享的决策：

**为什么选 Ken Burns 而不是 AI 视频生成？**

三个原因：（1）免费；（2）效果可控——AI 视频生成容易出"妖魔鬼怪"；（3）MV 场景够用——纪录片风格对于音乐影像来说审美上是成立的。

**为什么图片用 1280×720 再拉伸到 1080p？**

文心一格的最大输出分辨率限制。拉伸带来的轻微模糊反而给画面增加了一层柔焦效果，意外地适合音乐 MV 的质感。

**为什么用固定 prompt 模板而不是 voice clone？**

ACE API 目前不支持 voice clone。但意外的是，固定 prompt 模板反而带来了好处——声音的一致性可控，不会出现声音突变的问题。这其实是**约束带来品质**的案例。

## 未来方向

- **v1.1**：人工审核模式（`--review`）、卡拉OK 字幕
- **v2.0**：AI 视频生成（可灵/通义万相）、voice clone、数字人形象
- **v3.0**：多歌手协作、实时生成、社交媒体自动发布

## 小结

一个完整的 AI MV 制作管线，从歌词到成品视频，全程零成本。核心思路是**用 FFmpeg 的传统视频处理能力弥补 AI 视频生成的缺口**，用固定的 prompt 模板弥补 voice clone 的缺失。

这不是最炫的方案，但这是目前最务实的方案。
