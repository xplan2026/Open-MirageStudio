# 从零搭建 AI Agent 协作工作室：Mirage-Studio 架构设计

## 为什么要做这件事？

我是一个独立自媒体创作者，正在创作一部长篇连载小说《幻觉》。随着创作的深入，我发现传统的写作方式有一个明显的瓶颈：**内容形态单一**。小说只有文字，而读者期待更丰富的体验方式——音乐、视频、可视化。

如果每个环节都手工完成，我需要学习作曲、视频制作、族谱绘制……显然不现实。

解决方案：**让 AI Agent 各司其职，协作生产跨媒介内容**。

这就是 Mirage-Studio 的出发点。

## 整体架构

Mirage-Studio 是一个**独立自媒体 IP 工作室**，以长篇连载小说《幻觉》为基石，通过多个 AI Agent 协作，持续生产跨媒介内容（小说、歌曲、MV、族谱可视化），并通过官方网站对外展示。

核心设计理念：

> 《幻觉》小说是整个项目的骨架——它不一定要"完成"，而是在持续创作中变得越来越生动。补充信息越多，可供其他 Agent 创作的知识越丰富，工作室才有可持续生产的能力。

## 五个 Agent 的分工

| Agent | 定位 | 一句话描述 |
|--------|------|-----------|
| **Coordinator-Agent** | 统一调度层 | 意图解析 → 任务编排 → Agent 路由 |
| **Xujie Writer** | 小说创作（基石） | 人控 AI 辅助写作，管理设定与一致性 |
| **Zhupu Manager** | 族谱管理 | 辅助小说创作，管理角色家族关系 |
| **Lemong Agent** | AI 歌曲创作 | 从小说提取灵感或独立创作歌曲 |
| **Erhu Agent** | MV 制作 | 数字人歌手"二虎"的影像化呈现 |

### 关键约束

在设计中我们定下了几个约束：

1. **非自动联动**：小说更新**不自动**触发歌曲/MV 创作。所有下游创作需要用户明确指令。
2. **小说是基石但不是瓶颈**：即便小说未更新，也可基于已有章节独立创作歌曲和 MV。
3. **用户始终在回路中**：每个创作环节都需要用户确认或发起。

为什么这么设计？因为我们发现完全自动化会产生大量"垃圾内容"。用户必须对最终结果负责，AI 只是**增强**而非**替代**。

## 协作工作流

```
用户指令（微信 / Admin-UI / CLI）
        │
        ▼
┌──────────────────────┐
│   Coordinator-Agent   │  意图解析 + 任务编排 + Agent 路由
└──────┬───────────────┘
       │
       ├──────────────► Xujie Writer ────► 小说章节
       │                      │
       │                      ▼
       │               Zhupu Manager ──► 角色族谱数据
       │
       ├──────────────► Lemong Agent ────► 歌曲 MP3
       │                      │
       │                      ▼
       │               Erhu Agent ───────► 数字人 MV
       │
       └──────────────► 产物索引 → Website 展示
```

## 技术栈选择

整个项目跑在一台 4C4G 的云服务器上，所以技术选型必须考虑资源约束。

- **Coordinator**：Express + Node.js，HTTP 服务
- **Website**：Astro + Tailwind CSS，静态站点生成，1.8G 内存友好
- **AI 模型**：DeepSeek（文本）、ACE（音乐）、百度文心一格（图片）
- **视频合成**：FFmpeg Ken Burns 效果

选择 Astro 而不是 Next.js 是一个重要的决策。在 1.8G 可用内存下，Next.js 的 SSR 内存占用会挤压 Agent 的运行空间。Astro 的 SSG 模式完美解决了这个矛盾——构建时生成静态文件，运行时零开销。

## 一些经验分享

1. **先骨架后血肉**：先搭调度框架（Coordinator），再逐个开发 Agent。这样每个新 Agent 都有统一的接入方式和状态追踪。

2. **数据即产品**：所有 Agent 产出物统一在 `data/` 目录下管理，Website 在构建时直接读取。这形成了一个天然的内容管线。

3. **免费 API 优先**：MVP 阶段全部使用免费 API（DeepSeek 免费额度、ACE 免费 tier、百度文心免费额度），单首 MV 零成本。

4. **类型定义先行**：在写第一个页面之前，先定义好 TypeScript 类型。后续所有数据读取函数都基于统一类型，避免了大量的调试时间。
