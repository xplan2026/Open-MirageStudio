## 一、方案概述

将二虎从"图片幻灯片 MV"升级为**数字人歌手 MV**：

```
当前流程:  图片 → Ken Burns 效果 → 视频拼接 → MV
目标流程:  数字人形象 → 音频驱动表演 → 场景合成 → MV
```

### 核心理念

二虎拥有**专属数字人模型**，可跨作品重复调用。每首新歌只需：
1. 输入音频 → 数字人自动对口型表演
2. 叠加场景背景 → 渲染输出

---

## 二、整体流程

```
Phase 1: 数字人形象创建（一次性）
  ├─ 1.1 设计二虎形象描述
  ├─ 1.2 调用智谱文生图 → 生成正面照 + 多角度照
  ├─ 1.3 调用智谱数字人创建 API → 生成二虎数字人模型
  └─ 1.4 保存数字人 ID（持久化，跨作品复用）

Phase 2: 每首歌曲 MV 制作
  ├─ 2.1 lemong-agent 生成歌曲 (mp3)
  ├─ 2.2 场景图片生成（可视化背景）
  ├─ 2.3 调用数字人 API → 音频驱动口型表演视频
  ├─ 2.4 数字人表演 + 场景背景合成
  ├─ 2.5 叠加歌词字幕
  └─ 2.6 输出最终 MV
```

## 三、Phase 1: 数字人形象创建

### 3.1 二虎形象设计

**核心原则**: 生成的正面形象图将作为 wan2.2-s2v 对口型 / CogVideoX 图生视频的**参考图（Reference Image）**，用于所有后续视频片段保持人物一致性。

> ⚠️ **形象调整 (2026-08-21)**: 历史模型生成的二虎形象偏向韩国人/日本人（瓜子脸、韩式发型），不符合 IP 定位。目标形象改为 **西藏男性**，体现高原民族的粗犷、质朴、温暖气质。

#### 形象描述 prompt 模板（西藏男性）

```
一位西藏男性民谣/独立音乐人，约30岁出头，
国字脸，面部轮廓分明，颧骨略高，肤色为高原日晒的古铜色，
浓眉大眼，眼神坚毅而温暖，鼻梁挺直，嘴唇略厚，下颌硬朗，
黑色利落短发（藏式风格），
身穿藏式风格服装（藏袍/氆氇围巾/藏式衬衫），搭配绿松石、天珠等藏式配饰，
气质：高原民族的粗犷、质朴、温暖，
背景为雪山、草原、经幡或高原自然光，
写实摄影风格，高清，8K。
```

#### 需要生成的图片

| 序号 | 角度 | 用途 | 生成方式 |
|------|------|------|---------|
| 1 | 正面特写 | 数字人主参考图（i2v 输入） | 智谱 CogView-3-Flash |
| 2 | 正面半身 | 备用参考图 | 智谱 CogView-3-Flash |
| 3 | 微左侧 15° | 多角度一致性参考 | 智谱 CogView-3-Flash |
| 4 | 微右侧 15° | 多角度一致性参考 | 智谱 CogView-3-Flash |
| 5 | 正面闭眼深情 | 表情变体 | 智谱 CogView-3-Flash |

> **一致性策略**:
> - 用同一张正面照作为所有 CogVideoX i2v 调用的 `image_url`
> - 用不同的 `prompt` 描述动作/角度变化：如 "人物轻微侧头，嘴巴微动，像在唱歌"
> - CogVideoX 会在保持图片人物特征的基础上生成动态视频

## 四、Phase 2: 单首 MV 制作流程

### 4.1 歌曲生成（复用现有）

```
compose.js → lemong-agent → 歌曲 mp3 + 歌词
```

无变化，复用现有流程。

### 4.2 音轨分离（新增 — mvsep 在线服务）

对口型模型 wan2.2-s2v 要求音频**去除背景音乐、仅留清晰人声**，因此需先分离音轨：

```
歌曲 mp3 → mvsep API 分离 → vocals.wav（纯人声，供 wan2.2-s2v 驱动口型）
```

- **方案**: mvsep 在线服务（`docs/reference/mvsep操作指南.md`），无需本地 GPU
- **参考**: 仅保留 mvsep 一份（demucs/Spleeter/UVR 调研文档已删除，2026-08-21）
- **实现**: 新增 `scripts/stem.js` 封装 mvsep API

### 4.2 场景图片生成（复用现有）

```
visualize.js → 分析歌词 → DeepSeek 生成 prompt → 智谱生图
```

无变化，但图片用途从"幻灯片素材"变为**两种角色**：
- **数字人表演背景**（需要氛围感场景）
- **穿插空镜**（不需要人物，纯风景/意境图）

### 4.3 数字人动态视频生成（新增 — 基于 CogVideoX i2v）

**核心**: 同一张二虎正面参考图 + 不同动作描述 → 多个动态视频片段。

```javascript
// 为每个场景生成二虎的动态表演视频
// POST /api/paas/v4/videos/generations
{
  model: "cogvideox-flash",
  image_url: "<二虎正面照 URL>",          // 固定参考图
  prompt: "人物轻微摆动身体，嘴巴微动唱歌，眼神深情，镜头缓慢推进",  // 动作描述
  duration: 5,
  fps: 16,
  size: "720x480",
  quality: "speed"
}
```

**关键策略**：通过不同的 `prompt` 描述生成不同动态效果：

| prompt 示例 | 效果 |
|-------------|------|
| "人物正面站立，轻微晃动，嘴巴微动唱歌，镜头静止" | 基础表演 |
| "人物缓缓转头看向远方，眼神深邃" | 侧脸过渡 |
| "人物闭眼深情演唱，镜头缓慢推进特写" | 特写镜头 |
| "人物弹吉他，身体随节奏晃动" | 带动作 |

> ⚠️ **人物一致性**: CogVideoX 的 i2v 会保留输入图片的人物特征，但动作幅度大时可能有变形。建议动作描述保持保守（"轻微"、"缓慢"）。

### 4.4 合成渲染（改造 render.js）

```
┌─────────────────────────────────────┐
│  场景图片（背景层）                    │
│    +                                 │
│  二虎动态视频（前景层）               │
│    +                                 │
│  穿插空镜（无人物纯场景）              │
│    +                                 │
│  歌词字幕（drawtext）                 │
│    +                                 │
│  音频轨道                            │
│    =                                 │
│  最终 MV                             │
└─────────────────────────────────────┘
```

**镜头编排逻辑**：
```
段落类型        → 镜头策略
副歌（高潮）     → 二虎特写 + 场景切换快
A段/B段（叙事）  → 二虎半身 + 空镜穿插
前奏/间奏       → 纯空镜（无人物）
退出段           → 二虎远景 + 渐暗
```

## 六、API 与成本估算

### 6.1 一次性成本（形象创建）

| 项目 | API | 次数 | 单价 | 小计 |
|------|-----|------|------|------|
| 形象设计图 | CogView-3-Flash | 5 张 | ~0.05 元/张 | 0.25 元 |

### 6.2 每首 MV 成本（215s 歌曲示例）

| 项目 | API | 次数 | 单价 | 小计 |
|------|-----|------|------|------|
| 场景图片 | CogView-3-Flash | ~20 张 | ~0.05 元/张 | 1.00 元 |
| 二虎动态视频 | CogVideoX-Flash | ~10 段 | ~0.1-0.2 元/段 | 1.0-2.0 元 |
| 空镜 Ken Burns | 本地 FFmpeg | ~10 段 | 免费 | 0 元 |
| FFmpeg 合成 | 本地 | — | 免费 | 0 元 |
| **每首合计** | | | | **~2-3 元** |

> 对比当前全 Ken Burns 方案（~1.5 元/首），增加约 1-1.5 元，但获得动态人物表演。

### 6.3 混合策略（控制成本）

并非所有图片都需要 CogVideoX，可采用混合策略：

| 内容类型 | 技术 | 占比 | 说明 |
|----------|------|------|------|
| 二虎表演（副歌/重点段） | CogVideoX i2v | 30% | 动态人物 |
| 空镜/场景切换 | Ken Burns | 50% | 免费，静态图动画 |
| 转场/前奏/间奏 | 纯色渐变 | 20% | 免费 |

## 七、技术风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| CogVideoX 人物一致性不足 | 不同片段人物不像 | 固定 image_url + 保守动作描述 |
| 图生视频帧率低（16fps） | 画面不流畅 | RIFE 插帧到 25fps |
| 视频片段仅 5s | 需大量片段 | 混合 Ken Burns 空镜填充 |
| 人物图需公网 URL | 需上传步骤 | 智谱文件上传 API 或 自建 OSS |
| 异步生成耗时长 | 单段 2-5 分钟 | 并行调用多个任务 |
| 无真正口型同步 | 不是对口型 | 远景/半身镜头降低口型可见度 |
| 真正对口型需求 | 当前方案不支持 | 远期引入百度数字人/D-ID/MuseTalk |

## 九、CogVideoX 图生视频 API（已确认）

### 9.1 已确认的 API 端点

基于智谱 SDK v4 源码 (`zhipuai/api_resource/videos/videos.py`) 逆向确认：

| 功能 | 端点 | 方法 | 说明 |
|------|------|------|------|
| 创建视频任务 | `POST /api/paas/v4/videos/generations` | POST | 提交文生视频/图生视频任务 |
| 查询任务结果 | `GET /api/paas/v4/async-result/{id}` | GET | 轮询异步任务状态与结果 |

认证方式与现有智谱 API 一致：`Authorization: Bearer {ZHIPU_API_KEY}`

### 9.2 请求参数（图生视频 i2v）

```javascript
{
  model: "cogvideox" | "cogvideox-flash",  // 模型名（Flash 更快更便宜）
  image_url: "https://...",                // 输入图片 URL 或 Base64
  prompt: "动作描述文本",                    // 可选，描述图片如何动起来
  quality: "speed" | "quality",            // 速度优先 或 质量优先
  with_audio: false,                        // 是否生成音频（MV 场景用 false）
  size: "720x480",                          // 视频分辨率
  duration: 5,                              // 视频时长（秒）
  fps: 16                                   // 帧率
}
```

### 9.3 返回结构

```javascript
// 创建任务时返回
{
  id: "task_xxxxxxxx",           // 任务 ID（用于轮询）
  model: "cogvideox",
  task_status: "PROCESSING",     // PROCESSING | SUCCESS | FAIL
  request_id: "..."
}

// 任务完成时返回
{
  id: "task_xxxxxxxx",
  model: "cogvideox",
  task_status: "SUCCESS",
  video_result: [{
    url: "https://...",           // 视频下载 URL
    cover_image_url: "https://..." // 封面图 URL
  }],
  request_id: "..."
}
```

### 9.4 调用流程

```
POST /videos/generations → 获取 task_id → 轮询 GET /async-result/{id} → 获取 video_url
                                                    ↑ 间隔 5-10 秒轮询
```
